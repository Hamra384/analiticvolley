## Decisiones tomadas

- Un solo PR (#3) para S0+S1: CI recién existe en S1, así S0 también queda validado por CI.
- Branch protection sin revisión obligatoria: el agente opera con la cuenta del dueño y GitHub no permite aprobar
  un PR propio. El checkpoint humano del merge lo implementa `guard_bash` (`gh pr merge` → pide aprobación).
- Mínimo de 100 tests en CI (`--min-tests 100`): detecta colapsos de recolección; se sube a medida que crece la suite.
- Hooks con `python` del sistema y ruta relativa (más robusto entre shells en Windows que `$CLAUDE_PROJECT_DIR`).
